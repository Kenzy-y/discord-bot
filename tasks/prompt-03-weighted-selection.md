# Задача 3: умный выбор звуков (динамические веса и ограничение повторов)

## Контекст

Задачи 1 и 2 выполнены (последний коммит `147c423`). Сейчас бот в бесконечном режиме выбирает следующий звук равновероятно (`random.choice`). При малом числе звуков это ощущается как «не рандом»: один и тот же звук часто играет подряд.

Нужно заменить равновероятный выбор на выбор с динамическими весами и жёстким ограничением повторов.

Перед началом прочитай `CLAUDE.md`, `tasks/report-02.md` и текущий код `bot/session.py` и `bot/config.py`. Правила из `CLAUDE.md` действуют. Всё, что не касается выбора звука, не меняй: паузы, команды, перечитывание конфига перед каждым звуком, обработку ошибок, stage-каналы.

## Как должен работать выбор

### Состояние

Для каждого сервера бот хранит в памяти:

- **динамический множитель** каждого звука (по умолчанию 1.0);
- **историю** последних проигранных звуков (достаточно хранить последние `window` записей).

Состояние живёт, пока запущен бот, и **сохраняется между `/stop` и `/start`**, чтобы после перезапуска сессии не играл сразу тот же звук. На диск его сохранять не нужно: при перезапуске бота состояние сбрасывается.

### Алгоритм выбора следующего звука

Перед каждым звуком (после перечитывания `config.toml` и списка файлов, как сейчас):

1. **Синхронизация.** Новые файлы добавляются в состояние с множителем 1.0. Удалённые файлы убираются из состояния; их записи в истории можно оставить, на выбор они не влияют.
2. **Кандидаты.** Звуки с базовым весом больше 0 (см. `[weights]` ниже). Пусть их количество N. Если N = 0, сессия завершается так же, как при пустой папке.
3. **Эффективное окно.** `W = min(window, N × max_repeats)`.
   Правило «не больше `max_repeats` раз за `window` звуков» при малом N невыполнимо (например, 3 звука × 2 повтора = 6 < 10), поэтому окно сужается. При таком W всегда остаётся хотя бы один разрешённый звук: заблокированных не больше `(W − 1) / max_repeats`, а это меньше N. Если W стало меньше `window`, пиши об этом в лог при запуске сессии и при каждом изменении W (а не перед каждым звуком).
4. **Разрешённые звуки.** Звук запрещён, если среди последних `W − 1` проигранных он встречается `max_repeats` раз или больше. Тогда после добавления нового звука в любом окне из W подряд идущих звуков каждый встречается не больше `max_repeats` раз.
5. **Выбор.** Эффективный вес звука = базовый вес × динамический множитель. Звук выбирается среди разрешённых случайно, с вероятностью, пропорциональной эффективному весу.
6. **Обновление.** Сразу после выбора (до проигрывания — неудачный файл тоже считается проигранным, чтобы не выбираться снова и снова):
   - множитель выбранного звука становится равным `after_play`;
   - множитель каждого остального звука увеличивается на `growth`, но не выше `max_weight`;
   - выбранный звук добавляется в историю.

### Конфигурация

Добавь в `config.toml` новые секции, с комментарием на русском к каждому параметру. Комментарии должны объяснять смысл простыми словами: вес — это относительный шанс, а не проценты.

```toml
[selection]
# Множитель шанса звука сразу после того, как он прозвучал (обычный — 1.0)
after_play = 0.1
# На сколько растёт множитель звука каждый раз, когда играет другой звук
growth = 0.3
# Максимальный множитель: дольше этого шанс не растёт
max_weight = 3.0
# Звук не может прозвучать больше max_repeats раз за последние window звуков.
# Если звуков мало, окно автоматически сужается до (число звуков × max_repeats).
window = 10
max_repeats = 2

[weights]
# Базовый вес отдельных звуков. По умолчанию у всех 1.0.
# 0.5 — звук играет примерно вдвое реже, 2.0 — вдвое чаще, 0 — звук отключён.
# Имя файла пишется в кавычках, например:
# "rare-sound.ogg" = 0.3
```

Валидация (ошибки обрабатываются как сейчас: при `/start` — сообщение, посреди сессии — работа с последним корректным конфигом и одно предупреждение в лог):

- `after_play >= 0`, `growth >= 0`, `max_weight >= 1.0` (стартовый множитель 1.0 не должен превышать максимум), `max_weight >= after_play`;
- `window` и `max_repeats` — целые числа не меньше 1;
- значения в `[weights]` — числа не меньше 0;
- если секций `[selection]` или `[weights]` нет, используются значения по умолчанию, как выше. Старые конфиги не должны ломаться.

Особые случаи:

- имя в `[weights]`, которого нет в `sounds/`: предупреждение в лог один раз на изменение конфига, само значение игнорируется;
- имена в `[weights]` сравниваются с именами файлов без учёта регистра;
- если у всех разрешённых звуков эффективный вес 0 (например, `after_play = 0` и звук один), выбирай среди разрешённых равновероятно.

### Логирование

Строку проигрывания дополни шансом, с которым звук был выбран:

```
[12] играю boom.ogg (шанс 41%, звуков в папке: 3)
```

На уровне DEBUG перед выбором выводи таблицу всех звуков: базовый вес, множитель, разрешён ли звук.

## Архитектура

- Логику выбора вынеси в отдельный модуль (например, `bot/selector.py`) без зависимостей от Discord и asyncio. На вход: список звуков, настройки и генератор случайных чисел (`random.Random`). Состояние хранится внутри объекта.
- `SessionManager` получает селектор как подменяемую зависимость, по аналогии с `sleep` и `player`. Селекторы хранятся по серверам и переживают завершение сессии.

## Скрипт-симулятор

Добавь `tools/simulate_selection.py`. Он берёт реальную папку `sounds/` и реальный `config.toml` (или пути из аргументов) и прогоняет выбор без Discord и без пауз. Число итераций задаётся аргументом, по умолчанию 1000. Вывод на русском:

- сколько раз и в каком проценте случаев играл каждый звук;
- процент случаев, когда звук повторился сразу подряд;
- максимальное число повторов одного звука в любом окне из W звуков (должно быть не больше `max_repeats`);
- эффективное окно W.

Это инструмент владельца для подбора параметров. В `README.md` опиши, как его запускать и как читать вывод.

## Тесты

Используй `random.Random` с фиксированным seed, чтобы тесты были детерминированными.

- Ограничение окна не нарушается на длинном прогоне (10 000 выборов) при N = 1, 2, 3, 5, 10 и разных `window` и `max_repeats`, в том числе когда окно сужается.
- Выбор никогда не завершается ошибкой «нет разрешённых звуков» при N ≥ 1.
- Динамические веса работают: при N = 3 и настройках по умолчанию доля повторов сразу подряд заметно ниже 1/3.
- Базовые веса работают: звук с весом 0.3 на длинном прогоне играет заметно реже остальных; звук с весом 0 не играет никогда.
- Звук, добавленный во время работы, начинает выпадать; удалённый перестаёт выпадать без ошибок.
- Состояние сохраняется между двумя сессиями на одном сервере.
- Валидация новых полей конфига, включая отсутствие новых секций (старый конфиг).
- Все старые тесты проходят.
