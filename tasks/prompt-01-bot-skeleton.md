# Задача 1: каркас Discord-бота со случайным воспроизведением звуков

## Контекст проекта

Discord-бот, который заходит в голосовой канал и проигрывает звуки из папки `sounds/` в случайном порядке со случайными паузами. Звуки добавляют вручную владелец и люди с доступом к GitHub-репозиторию — обычными коммитами. Бот запускается на домашнем ПК владельца. Доступ к Discord идёт через системный VPN (Discord заблокирован в России): это вне зоны ответственности кода, но учитывай при диагностике сетевых ошибок.

Работаем итерациями, это первая задача. Делай только то, что описано ниже. Если считаешь, что нужно что-то сверх этого, предложи в отчёте, но не реализуй.

Рабочая директория — корень репозитория (если git ещё не инициализирован, инициализируй).

## Стек (обязательно)

- **Python 3.11+** (нужен встроенный `tomllib`).
- **`discord.py[voice]` не ниже 2.7.1.** С марта 2026 Discord требует для голосовых подключений протокол сквозного шифрования DAVE. Поддержка появилась в discord.py 2.7.0 и работает через пакет `davey`, который ставится с extra `voice`. Без него подключение к голосовому каналу падает с кодом закрытия 4017. Если твои знания о голосовом API discord.py расходятся с установленной версией, сверяйся с установленной версией, а не с памятью. Если для выбранной версии Python у `davey` нет готовой сборки, используй версию Python, для которой она есть, и напиши об этом в отчёте.
- **FFmpeg** для воспроизведения файлов (должен быть доступен в PATH).
- **`python-dotenv`** для загрузки секретов из `.env`.
- Все зависимости — в `requirements.txt` с минимальными версиями.
- Не включай привилегированные intents (message content, members, presence): для слэш-команд и голоса они не нужны.

## Секреты и окружение

`.env` (в `.gitignore`), пример — в `.env.example`:

- `DISCORD_TOKEN` — токен бота.
- `GUILD_ID` — необязательный. Если задан, слэш-команды синхронизируются только на этот сервер (мгновенно, удобно для тестов). Если не задан — глобальная синхронизация.

Токен никогда не должен попадать в репозиторий или в логи.

## Конфигурация

`config.toml` в корне, с комментарием на русском к каждому параметру:

```toml
[playback]
# Пауза между звуками в секундах (каждый раз выбирается случайно из диапазона)
pause_min = 5
pause_max = 30
# Сколько звуков проиграть за один /start (выбирается случайно из диапазона)
plays_min = 3
plays_max = 10
```

- Конфиг перечитывается при каждом `/start`, чтобы изменения после `git pull` применялись без перезапуска бота.
- Валидация: все значения неотрицательные, `plays_min >= 1`, `min <= max`. При ошибке — понятное сообщение в лог и в ответ на команду, сессия не запускается.
- Позже сюда добавятся другие настройки случайности, поэтому загрузку конфига сделай так, чтобы её было легко расширять.

## Команды

Все команды — слэш-команды. Ответы бота на русском, короткие. Сообщения об ошибках — ephemeral (видны только автору команды). Подключение к голосу может занять больше 3 секунд, поэтому в командах, которые подключаются к каналу, сначала делай `defer`, а потом отвечай через followup.

### /connect

- Если автор команды сидит в голосовом канале — бот подключается к этому каналу.
- Если автор не в голосовом канале — бот выбирает **случайный** голосовой канал на этом сервере из подходящих: у бота есть права Connect и Speak, канал не заполнен до лимита пользователей, это не AFK-канал сервера.
- Если бот уже подключён к голосовому каналу на этом сервере — перемещается в нужный канал, а не создаёт второе подключение.
- Если подходящих каналов нет — сообщает об этом.

### /start

- Если бот не подключён к голосовому каналу на этом сервере — сначала выполняет логику `/connect`.
- Если на этом сервере сессия уже идёт — отвечает, что уже играет, и не запускает вторую.
- Сессия:
  1. Перечитывает `config.toml` и список файлов в `sounds/`. Поддерживаемые расширения: `.ogg`, `.opus`, `.mp3`, `.wav`. Если подходящих файлов нет — сообщает об этом и не запускается.
  2. Выбирает случайное целое N из `[plays_min, plays_max]`.
  3. N раз: выбирает случайный файл, проигрывает его до конца, затем ждёт случайную паузу (дробное число секунд из `[pause_min, pause_max]`). После последнего звука пауза не нужна — сессия завершается.
- Для воспроизведения используй `FFmpegOpusAudio.from_probe` (или актуальный аналог в установленной версии), чтобы файлы, уже закодированные в Opus, не перекодировались.
- Сессия работает как фоновая asyncio-задача, по одной на сервер, и не блокирует обработку других команд.
- Если бота отключили от голосового канала во время сессии (кикнули, сеть упала), сессия корректно завершается без падения бота.

### /stop

- Останавливает текущую сессию и текущий звук. Бот остаётся в канале.
- Если сессии нет — сообщает об этом.

### /leave

- Останавливает сессию (если есть) и отключается от голосового канала.

## Надёжность и логирование

- Логирование через модуль `logging`, уровень INFO, вывод в консоль. Логируй подключения, начало и конец сессий, какой звук играет, ошибки.
- Ошибка в одной сессии или команде не должна ронять бота.
- При запуске бот проверяет и пишет понятное предупреждение, если: FFmpeg не найден, пакет `davey` не установлен, папки `sounds/` нет или она пуста.
