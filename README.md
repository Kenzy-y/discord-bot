# Discord-бот случайных звуков

Бот заходит в голосовой канал и проигрывает звуки из папки `sounds/` в случайном порядке со случайными паузами.

## 1. Создание бота в Discord

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications) → **New Application**, задайте имя.
2. Раздел **Bot** → **Reset Token** → скопируйте токен. Это пароль бота: никому не показывайте и не коммитьте.
   Привилегированные intents (Presence, Server Members, Message Content) включать **не нужно**.
3. Раздел **OAuth2** → **URL Generator**:
   - Scopes: `bot`, `applications.commands`;
   - Bot Permissions: **View Channels**, **Connect**, **Speak**.
4. Откройте сгенерированную ссылку и добавьте бота на свой сервер.
5. ID сервера (для `GUILD_ID`): в Discord включите *Настройки → Расширенные → Режим разработчика*, затем ПКМ по серверу → **Копировать ID сервера**.

## 2. Установка

### Python

Нужен Python **3.11 или новее** (проверено на 3.12). Windows: установщик с [python.org](https://www.python.org/downloads/) (отметьте «Add python.exe to PATH»). Linux: пакет `python3` и `python3-venv` из репозитория дистрибутива.

### FFmpeg

FFmpeg должен быть доступен в `PATH` (вместе с ним обычно ставится `ffprobe`, он тоже используется).

- **Windows:** `winget install Gyan.FFmpeg`, затем перезапустите терминал. Или скачайте сборку с [gyan.dev](https://www.gyan.dev/ffmpeg/builds/), распакуйте и добавьте папку `bin` в `PATH`.
- **Linux:** `sudo apt install ffmpeg` (Debian/Ubuntu), `sudo dnf install ffmpeg` (Fedora), `sudo pacman -S ffmpeg` (Arch).

Проверка: `ffmpeg -version`.

### Зависимости

Windows (PowerShell):

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Проверка: `python -m discord --version` — в выводе должна быть строка `davey`. Без пакета `davey` Discord не пустит бота в голосовой канал (ошибка 4017: с марта 2026 голос требует сквозного шифрования DAVE).

### Настройка `.env`

Скопируйте `.env.example` в `.env` и заполните:

- `DISCORD_TOKEN` — токен бота;
- `GUILD_ID` — необязательно. Если указан, команды появятся на этом сервере сразу. Если пусто, команды регистрируются глобально, это может занять до часа.

## 3. Запуск

```bash
python -m bot
```

(в активированном виртуальном окружении, из корня репозитория). Остановка: `Ctrl+C`.

При запуске бот предупреждает в логе, если не найден FFmpeg, не установлен `davey` или нет звуков.

## 4. Команды

| Команда | Что делает |
|---|---|
| `/connect` | Заходит в ваш голосовой канал. Если вы не в голосе — в случайный обычный голосовой канал, где у бота есть права Connect и Speak, есть места и который не является AFK-каналом. Если бот уже в другом канале — переходит. Stage-каналы не поддерживаются. |
| `/start` | Запускает бесконечное воспроизведение: случайный звук → случайная пауза → снова случайный звук, пока не остановят. Первый звук играет сразу. Если бот не в голосе — сначала подключается как `/connect`. |
| `/stop` | Останавливает воспроизведение и текущий звук. Бот остаётся в канале. |
| `/leave` | Останавливает сессию и выходит из голосового канала. |

Ошибки видны только тому, кто вызвал команду.

Воспроизведение также завершается само, если бота отключили от голосового канала, если папка `sounds/` опустела или если 5 звуков подряд не удалось воспроизвести (битые файлы). Причина пишется в лог.

В логе для каждого звука видны номер, имя файла, шанс, с которым он был выбран, число звуков в папке и выбранная пауза:

```
Сервер X: [12] играю boom.ogg (шанс 41%, звуков в папке: 3)
Сервер X: [12] пауза 7.3 с
```

Как выбирается звук, описано в разделе «Настройки `config.toml`».

## 5. Как добавлять звуки

Положите файлы в подпапки `sounds/short/` (для коротких звуков) и `sounds/long/` (для длинных звуков) и закоммитьте. Перед воспроизведением бот сначала случайно выбирает тип звука (`short` или `long`), а затем выбирает конкретный файл из соответствующей папки. Если одна из папок пуста, бот играет звуки из доступной папки.

Поддерживаемые форматы: `.ogg`, `.opus`, `.mp3`, `.wav`. Расширения сравниваются без учёта регистра (`.MP3` тоже подходит). Список файлов перечитывается перед каждым звуком, так что после `git pull` новые звуки начнут играть без перезапуска и без `/stop`.

Рекомендуемый формат — **Ogg Opus**: Discord передаёт звук в Opus, поэтому такие файлы идут без перекодирования, а весят мало. Конвертация:

```bash
ffmpeg -i sound.mp3 -vn -c:a libopus -b:a 96k sound.ogg
```

Флаг `-vn` выкидывает видеопотоки: без него обложка из mp3 может попасть в итоговый файл как видео.

## 6. Настройки `config.toml`

Перечитываются перед каждым звуком: изменения применяются без перезапуска бота и без `/stop`. Если файл стал некорректным во время воспроизведения, бот продолжает с последними корректными настройками и один раз пишет предупреждение в лог.

Если конфиг некорректен в момент `/start`, бот пишет ошибку в лог и в ответ на команду, воспроизведение не запускается. Неизвестные параметры игнорируются. Секции `[selection]` и `[weights]` необязательны: без них используются значения по умолчанию.

### `[playback]` — паузы

| Параметр | Смысл |
|---|---|
| `pause_min`, `pause_max` | Пауза между звуками в секундах. Каждый раз выбирается случайное дробное число из диапазона. Значения неотрицательные, `pause_min <= pause_max`. |

### `[selection]` — как выбирается следующий звук

Звук выбирается не равновероятно. У каждого звука есть **шанс** — относительное число, а не проценты: звук с шансом 2 выпадает вдвое чаще звука с шансом 1. Шанс = базовый вес из `[weights]` × динамический множитель.

- Только что прозвучавший звук получает множитель `after_play` (по умолчанию 0.1), то есть почти не выпадает следующим.
- Каждый раз, когда играет другой звук, его множитель растёт на `growth`, но не выше `max_weight`. Чем дольше звук не играл, тем выше у него шанс.
- Жёсткий лимит: звук не может прозвучать больше `max_repeats` раз за последние `window` звуков. Если звуков мало, окно сужается до `(число звуков − 2) × max_repeats + 1`, чтобы на каждом шаге оставалось минимум 2 варианта. Иначе выбор превратился бы в повторяющийся цикл. При 3 звуках окно равно 3: запрещено только три одинаковых подряд, а повторы подряд и так редки благодаря `after_play`. При 1–2 звуках лимит не действует.
- Множители и история хранятся в памяти бота отдельно для каждого сервера и сохраняются между `/stop` и `/start`. При перезапуске бота они сбрасываются.

| Параметр | По умолчанию | Смысл | Ограничения |
|---|---|---|---|
| `after_play` | 0.1 | Множитель звука сразу после проигрывания | `>= 0`, `<= max_weight` |
| `growth` | 0.3 | Прибавка к множителю, пока играют другие звуки | `>= 0` |
| `max_weight` | 3.0 | Потолок множителя | `>= 1.0` |
| `window` | 10 | Длина окна для лимита повторов | целое `>= 1` |
| `max_repeats` | 2 | Сколько раз звук может прозвучать за окно | целое `>= 1` |

### `[weights]` — базовые веса отдельных звуков

По умолчанию вес каждого звука 1.0. Вес 0.5 — звук играет реже, 2.0 — чаще, 0 — звук отключён. Имя файла пишется в кавычках, регистр букв не важен:

```toml
[weights]
"rare-sound.ogg" = 0.3
"favorite.mp3" = 2
```

Динамические множители частично сглаживают базовые веса: редкий звук долго не играет, и его множитель успевает вырасти. Поэтому «вдвое реже» получается примерно, а не точно. Реальные доли покажет симулятор. Если в `[weights]` указан файл, которого нет в `sounds/`, бот пишет предупреждение в лог.

### Симулятор: подбор параметров

Симулятор прогоняет выбор звуков на реальной папке `sounds/` и реальном `config.toml` без Discord и без пауз:

```bash
python tools/simulate_selection.py              # 1000 выборов
python tools/simulate_selection.py -n 10000     # больше выборов — точнее доли
python tools/simulate_selection.py --seed 1     # повторяемый результат
python tools/simulate_selection.py --sounds другая/папка --config другой.toml
```

Как читать вывод:

- **таблица звуков** — сколько раз и какую долю времени играл каждый звук и какой у него базовый вес. Так видно, насколько `[weights]` меняет частоту;
- **«Повтор того же звука сразу подряд»** — как часто звук повторялся сразу. Для сравнения показано, сколько было бы при равновероятном выборе. Если повторов слишком много, уменьшите `after_play`;
- **«Эффективное окно W»** — окно, в котором действует лимит `max_repeats`, и было ли оно сужено из-за малого числа звуков;
- **«Максимум повторов одного звука в любом окне»** — должно быть не больше `max_repeats` («в норме»).

Чтобы увидеть шансы всех звуков перед каждым выбором прямо в работающем боте, включите уровень DEBUG для логгера сессий. Для этого временно добавьте в `bot/__main__.py` после `logging.basicConfig(...)` строку:

```python
logging.getLogger("bot.session").setLevel(logging.DEBUG)
```

Тогда перед каждым звуком в лог пишется таблица: базовый вес, множитель, шанс и разрешён ли звук. Включать DEBUG для всего приложения не стоит: discord.py начнёт писать в лог очень много служебных сообщений.

## 8. VPN

Discord заблокирован в России, поэтому боту нужен VPN, который работает **на всю систему** (не только в браузере) и **пропускает UDP**: текстовая часть Discord работает по HTTPS/WebSocket, а голос — по UDP. Типичные симптомы проблем с VPN:

- бот не запускается с ошибкой «Нет связи с Discord» — VPN выключен;
- бот онлайн и отвечает на команды, но не может подключиться к голосу (таймаут) — VPN не пропускает UDP.
